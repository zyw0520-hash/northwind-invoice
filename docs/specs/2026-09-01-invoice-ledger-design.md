# 德国工厂应付单据防漏记台账 — 设计文档

日期：2026-09-01
状态：已确认（用户逐段确认设计）

## 1. 背景与目标

用户在工厂做应收应付会计，需处理德国子公司（小工厂，无正式采购流程，员工经厂长口头授权自行下单）的大量应付单据：发票（Rechnung）、送货单（Lieferschein）、关税通知、罚单、租车费等。痛点：

1. 采购信息滞后——往往发票到了才知道买了什么；
2. 已发生发票漏记；
3. 用户不懂德语，处理德国发票需反复查词、追问同事。

**目标**：做一个防漏记的应付单据台账 Web 应用。核心不是严格三单匹配（无正式 PO，强匹配不现实），而是通过"三个哨兵 + 基础防护"主动发现漏记风险。

**非目标**（明确不做）：
- 手机端/PWA 适配（用户纯电脑端办公）
- 正式采购审批流
- 与财务系统（如 DATEV）自动对接
- 邮箱自动拉取发票（本期不做，见下方将来扩展路径；本期发票 PDF 靠手动拖入，流程见 §5.2/§7）

**将来扩展路径（仅预留，不实现）**：邮箱自动拉取将通过 Supabase Edge Function 实现（浏览器无法直连 IMAP）。多邮箱源设计已预留：每个源按类型选协议——Outlook/M365 走 Graph API OAuth2（需一次性 Azure 应用注册拿 client_id，首次浏览器授权，不存密码只存令牌，可随时撤销）；QQ/163/GMX 等走 IMAP+授权码。Edge Function 定时拉含 PDF 附件的新邮件 → 存 Storage → 进收件箱列表（按 message-id 判重）→ 一键转单衔接识别管线。

## 2. 用户与使用模式

- 单用户（用户本人），电脑浏览器使用；架构预留将来多人扩展（Supabase 账号）。
- 每日三种录入动作：
  1. 收到发票 → 录入（约 30 秒，含 PDF 识别预填）
  2. 看到送货单 → 快速录入（约 10 秒）
  3. 听到采购风声 → 新增采购线索（约 10 秒）
- 每天打开应用第一眼看"工作台"体检卡，无需主动查表。

## 3. 技术栈与架构

复用现有 ledger-app（d:\AI\ledger-app）的成熟模式：

| 层 | 选型 |
|---|---|
| 前端 | 纯静态 HTML + CSS + 原生 JS（ES modules），桌面浏览器优先布局（宽表格、多列、键盘友好） |
| 本地存储 | IndexedDB（Dexie.js） |
| 云同步 | Supabase（Postgres + REST），沿用 ledger-app 的同步模式 |
| PDF 文本提取 | pdf.js（有文本层的电子发票，占大多数） |
| OCR 兜底 | Tesseract.js 德语模型（扫描件/照片，无文本层时） |
| 部署 | GitHub Pages（新目录 invoice-ledger），SW 缓存版本化沿用 ledger-app 模式 |

同步触发：应用启动、数据改动（3 秒去抖）、断网恢复（online 后 1 秒）、切回前台、每 5 分钟轮询。Supabase API 响应先读文本再解析 JSON（兼容 201 空响应体）。每次拉取合并后执行去重。

## 4. 数据模型（三张主表）

### 4.1 documents 应付单据（统一表，类型区分）

| 字段 | 说明 |
|---|---|
| id | UUID 字符串主键 |
| type | 发票 / 送货单 / 贷项通知单 / 关税通知 / 罚单 / 租车费 / 其他 |
| supplier_id | 关联供应商 |
| doc_number | 单据号（发票号或送货单号） |
| doc_date | 单据日期 |
| net_amount / tax_rate / tax_amount / gross_amount | 净额、税率、税额、总额（EUR，两位小数）；税额可自动算 |
| due_date | 付款到期日（可自动推算：如发票日期+14/30 天；关税罚单手填） |
| pay_status | 未付 / 已付 / 部分付 / 待确认 / 争议中 / 催缴中（"已逾期"由系统按到期日自动算，不作为存储枚举；"部分付"仅作状态标记，不设已付金额字段） |
| pay_date / pay_method / counterparty_iban | 付款信息 |
| summary / cost_center | 商品服务摘要、成本中心 |
| archive_note | 文件存档位置（文件名/路径备注） |
| related_delivery_id | 挂到的送货单 id（发票↔送货单软关联） |
| related_lead_id | 关联的采购线索 id（票到销账用） |
| pdf_blob | PDF 文件二进制（存 IndexedDB，可回看） |
| ocr_status | 未上传 / 已识别 / 识别失败 / 手动 |
| created_at / updated_at | 同步与冲突判断用 |

### 4.2 leads 采购线索（预登记）

| 字段 | 说明 |
|---|---|
| id | UUID |
| ordered_by | 下单人（如 Alex） |
| supplier_id | 可空（未确认供应商先不填） |
| description / est_amount | 内容描述、预估金额（可空） |
| registered_date / expected_date | 登记日期、预计到票日期（可空） |
| status | 等票中 / 已销账 / 已取消 |
| resolved_doc_id | 销账后指向的票据 id |

### 4.3 suppliers 供应商

| 字段 | 说明 |
|---|---|
| id | UUID |
| name | 标准名称 |
| aliases | 别名列表（如 Raiffeisen Weser-Elbe eG ↔ WRE） |
| default_pay_days | 默认付款条件天数（0 = 手填到期日） |
| note | 备注 |

### 4.4 settings

提醒阈值（线索催票天数、送货单等票天数、画像倍数）、Supabase 配置、同步状态。

## 5. 页面与核心流程（桌面端）

左侧导航：**工作台 / 单据台账 / 采购线索 / 供应商 / 设置**。

### 5.1 工作台（首页）

- 体检卡四数字：🔴逾期未付数、🟠挂起等票数、🟡未销账线索数、⚠️可疑缺口数
- 今日待办列表（按紧急度排序：逾期 > 挂起超期 > 催票 > 可疑缺口）
- 最近动态（今日新增单据等）

### 5.2 三种录入路径

1. **收到发票**：新建单据 → 可选拖入 PDF → 自动识别预填（高亮"自动填的，请核对"）→ 下拉挂送货单/线索（可选）→ 保存
2. **看到送货单**：快速录入：供应商 + 单据号 + 日期（金额可不填）→ 自动进入"挂起等票"
3. **听到采购风声**：新增线索：下单人 + 内容 + 预估金额 → 完成

### 5.3 单据台账

主表格：排序/筛选（供应商、类型、状态、日期）、行点击编辑、CSV 导出（UTF-8 BOM，Excel 直开）。

### 5.4 德语小抄

录入表单字段旁悬浮中德对照，内置约 20 个常用词：Rechnungsnummer=发票号、Rechnungsdatum=发票日期、Lieferschein=送货单、Lieferant=供应商、Netto=不含税净额、MwSt./USt.=增值税、Gesamtbetrag/Bruttobetrag=含税总额、Fällig am/Zahlbar bis=到期日、Zahlungsziel=付款期限、Kontosumme=账户金额、Zzgl.=另加、IBAN、Verwendungszweck=用途等。

## 6. 防漏记机制（三哨兵 + 基础防护）

| 机制 | 规则 | 默认阈值 | 可调 |
|---|---|---|---|
| 哨兵1 线索催票 | 线索"等票中"超过 N 天 → 工作台提醒 | 14 天 | ✓ |
| 哨兵2 送货单等票 | 送货单后 N 天无关联发票 → 提醒"票可能没来" | 14 天 | ✓ |
| 哨兵3 供应商画像 | 距该供应商上次开票 > 历史间隔中位数 × 1.5 且 > 21 天 → 可疑缺口 | 历史 ≥3 张票才启用 | ✓ |
| 重复拦截 | 同供应商 + 发票号重复 → 保存时红色警告（可强制继续） | — | 强制 |
| 到期红黄灯 | 未付+已到期红 / 7 天内到期黄 | — | 强制 |
| 金额差异提示 | 发票挂送货单时总额差 >5% → 温和提示（可能是运费/部分开票） | 5% | ✓ |

## 7. PDF 识别管线（纯前端）

1. 拖入/选择 PDF → pdf.js 提取文本层
2. 正则匹配德语关键词（含常见变体、数字格式 1.234,56）→ 预填表单，自动填的字段高亮标注
3. 无文本层（扫描件/照片）→ 自动切换 Tesseract.js 德语 OCR（数秒~十几秒），同样预填
4. 识别失败/低置信度 → 静默降级手动填写，不阻塞录入；PDF 原文件仍保存，可随时回看
5. 定位：辅助预填、人工确认，非全自动

## 8. 数据安全与错误处理

- IndexedDB 本地存 + Supabase 自动同步（触发时机见 §3）
- 每日首次打开自动全量快照，保留最近 7 份，支持恢复与导出 JSON
- 同步冲突：updated_at 后写胜出；同步前自动备份
- Supabase 推送兼容 201+空响应体；拉取合并后去重（按 doc_number+supplier 等业务键）
- 编辑保存直接使用 UUID 字符串，禁止 Number() 转换
- PDF 识别失败静默降级；同步状态指示器沿用四态（🟢已同步/🟡待推送/🔴失败/🔵同步中）

## 9. 测试

- selftest 自测脚本（页面内运行），覆盖：
  - 德语正则解析（用真实样例发票文本做用例）
  - 三哨兵计算逻辑（边界：天数恰好、倍数边界、历史票不足 3 张）
  - 重复检测、线索销账、金额差异提示
  - 同步合并与去重
- 部署前跑一遍 selftest 全绿

## 10. 分阶段实施

- **阶段 1（MVP）**：三张表 + 三种录入 + 工作台/台账/线索/供应商页面 + 哨兵1/2 + 重复检测 + 到期灯 + 金额差异提示 + CSV 导出 + Supabase 同步 + 每日自动快照 + selftest。PDF 附件在阶段 1 仅支持存储与回看（pdf_blob + ocr_status="未识别"），不做识别
- **阶段 2**：PDF 识别管线（pdf.js + Tesseract.js）+ 德语小抄 + 哨兵3 供应商画像
- **阶段 3（将来可选）**：多人账号（Supabase Auth + 行级权限）；邮箱自动拉取（Edge Function 多邮箱源，路径见 §1）
